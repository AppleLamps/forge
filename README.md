# Nitrologic Forge

**Version:** 1.0.3

Nitrologic Forge is a command-line research tool designed for interacting with various large language models (LLMs) from different providers. It streamlines testing, file sharing, context management, and cost tracking across multiple AI platforms within a unified interface. Built with Deno.

## Key Features

* **Multi-Provider Support:** Interact with models from OpenAI, DeepSeek, XAI, and Google Gemini through their respective APIs.
* **Command-Line Interface:** Rich CLI for managing models, sessions, files, and configuration.
* **File Sharing & Context Management:** Share local files or entire directories with the selected model to provide context for your interactions. Forge automatically handles reading text files and encoding binary files. It tracks changes and updates the context accordingly.
* **Cost Tracking:** Monitors token usage (prompt, completion, cached) and estimates costs based on provider rates specified in `modelrates.json`. Tracks account balances.
* **Session Management:** Save and load conversation histories. Experimental support for session stacking (`/begin`, `/finish`).
* **Model Configuration:** Easily switch between models, adjust parameters like temperature, and view model details and pricing.
* **Tool Use:** Supports models with function calling/tool use capabilities. Includes built-in tools for getting time and submitting files generated by the model. Allows model annotation of shares, tags, or code.
* **Customizable Output:** Optional ANSI markdown rendering for chat responses. Configurable verbosity and logging.
* **Tagging System:** Organize shared files using tags. Models can annotate tags via tool use.

## Prerequisites

* **Deno:** The application is built using the Deno runtime. Installation instructions can be found at [https://deno.land/](https://deno.land/).
* **API Keys:** You need API keys for the desired AI providers (DeepSeek, XAI, OpenAI, Gemini).

## Installation & Setup

1. **Clone the Repository (if applicable):**
    ```bash
    git clone <your-repository-url>
    cd forge
    ```

2. **Configure API Keys:**
    * Obtain API keys from the respective providers.
    * Set the corresponding environment variables as defined in `accounts.json`:
        * `DEEPSEEK_API_KEY`
        * `XAI_API_KEY`
        * `OPENAI_API_KEY`
        * `GEMINI_API_KEY`
    * Alternatively, modify `accounts.json` if environment variables are not preferred (ensure this file is kept secure).

3. **Review Model Rates:**
    * Check `modelrates.json` for defined models and their pricing. Update or add models as needed.

4. **Build (Optional):**
    * Use `build.sh` (Linux/macOS) or `build.bat` (Windows) to create a standalone executable. The script compiles `forge.js` and copies necessary configuration files into a distribution directory (`forge-rc3` or `rc3`).
    * The build process requires Deno's compile capability.

## Usage

* **Running:**
    * **Directly with Deno:**
        ```bash
        # Linux/macOS
        ./run.sh
        # Windows
        .\run.bat
        ```
    * **Using the built executable:**
        ```bash
        ./forge-rc3/forge  # Or .\rc3\forge.exe on Windows
        ```

* **Basic Interaction:**
    * Type your prompts directly and press Enter.
    * To send a multi-line prompt, press Enter after the first line; subsequent lines will start with `+`. Press Enter on an empty `+` line to send the full prompt.
    * Enter `exit` to quit the application.

* **Commands:** Use `/` followed by a command name (e.g., `/help`, `/model`, `/share`). Many commands list items with indices; enter `#` followed by the index number to select an item.

### Common Commands

* `/help`: Display help information (shows content from `forge.md`).
* `/model [index|name|all]`: List available models or switch to a specific model.
* `/share <file_or_directory_path>`: Add a file or the contents of a directory to the list of shared items.
* `/push [tag]` or `/commit [tag]`: Update the model's context with the latest versions of shared files (optionally filtered by tag). This happens automatically on start if `commitonstart` is enabled.
* `/drop`: Remove all currently shared files from the model's context.
* `/history`: Show a summary of the current conversation history.
* `/save [name]`: Save the current chat history to a JSON file in the `foundry` directory.
* `/load [index|filename]`: Load a previously saved chat history.
* `/reset`: Clear the current conversation history and drop all shared files.
* `/config [index|flag_name]`: View or toggle configuration flags.
* `/temp [value]`: Set or display the model's temperature setting.
* `/credit [index|account_name]`: View account balances or select an account to manually adjust its credit.

**For a full command reference, see [forge.md](forge.md).**

## Configuration

* **`accounts.json`:** Defines provider API endpoint URLs and the environment variables used for API keys.
* **`modelrates.json`:** Specifies pricing per token (input, cached, output) for different models, used for cost estimation. Also includes flags like `stone` for models that don't support temperature changes.
* **`forge.json`:** Stores application state, including configuration flags (`config`), tags (`tags`), shared file metadata (`sharedFiles`), saved session names (`saves`), internal counters (`counters`), model usage statistics (`mut`), and account credit balances (`lode`). This file is read on startup and written to periodically.

* **Flags (via `/config`):** Control various behaviors like ANSI output, logging, automatic file commits, tool usage, etc.
